# MarketCase M11 — a step-by-step trace for every investigation

Status: approved by the user 2026-10-03 ("Trace view might be the simplest to implement").

## Why

24 of the 82 postings in the user's pipeline ask for observability or tracing of AI systems, and 14 for cost or latency. A case today stores only totals: one summed token count and cost for both model calls, and a runtime per receipt. Nobody can see where the 15 seconds or the $0.15 went, whether planning needed a retry, or how many sentences the verifier removed. M11 records that and shows it on the case page.

## Decisions

1. **Spans, recorded by the server, stored in the store.** New table `case_trace(case_id, seq, parent_seq, kind, name, started_at, ms, status, detail_json)`, `kind` ∈ `stage | tool | llm`. Written once per investigation, in a `finally`, so a case that fails half way still shows how far it got. No prompts or model output are stored (size, and the page is public); only counts, timings, cost and status.
2. **One small tracer, passed by context.** `gridcase/trace.py`: a `Tracer` with a `span(kind, name, **detail)` context manager (wall-clock ms, status ok/error, error message on exception, re-raises) and a `contextvars.ContextVar` holding the active tracer. `run_tool` records a `tool` span (name = tool, detail = step id if known, receipt id, inputs) only when a tracer is active, so the question box and the digest are untouched.
3. **What `investigate()` records**, in order, as top-level spans: `compare` (stage, wraps kpi.compare), `plan` (llm: attempts, input/output tokens, cost, model), `execute` (stage; its tool spans are children), `explain` (llm: tokens, cost, model), `verify` (stage: sentences kept, dropped, marked as interpretation), `publish` (stage). The `plan` and `explain` usages are the two values `investigate` already receives (`usage`, `u2`), so the trace's cost adds up to the case's `cost_usd` exactly.
4. **The deterministic re-check, the question box and the digest are not traced in M11.** `REVIEW:` the question box is the most-used public surface but keeps no record of questions; tracing it means deciding whether to store questions first.
5. **API**: `GET /api/cases/{case_id}/trace` → `{recorded, spans, totals}`; each span carries `offset_ms` from the case start. Totals: wall time, model calls, tokens in/out, cost, checks run, checks failed. Cases from before M11 return `recorded: false`.
6. **UI** (CaseView, full width under the three panels): a panel **"Step by step"**, hint "What the investigation did, in order, how long each step took and what it cost." Collapsed behind a button "Show the timeline". A totals line: "Took 14.2 s · 2 model calls · $0.15 · 9 checks, 1 couldn't run". Then a waterfall: one row per span with a plain label, a bar positioned by offset and sized by duration (grey; amber for model calls, which is where time and money go), the duration, and the cost on model rows. Tool rows are indented under "Ran the checks" and labelled with the existing `stepQuestion(tool, inputs)`. Labels: compare → "Measured the change"; plan → "Planned the checks" (+ " (2 tries)" when attempts > 1); execute → "Ran the checks"; explain → "Wrote the explanation"; verify → "Checked every sentence against the evidence" with "kept 6, removed 1"; publish → "Saved the case". A failed tool row says "couldn't run". Engine ids, tool names and model names appear only in `title` tooltips (the plain-language test's rule). Unrecorded cases: "Step-by-step timing is recorded for investigations from 3 October 2026 on."

## Exit test (written first, run red)

- `tests/exit/test_m11.py`: an investigation with the FakeLLM writes spans in the order above, tool spans are children of `execute` and one per executed step (a planted failing step is an `error` span with its message), offsets and durations are non-negative and children sit inside their parent, trace cost equals the case's `cost_usd`, a failure inside `explain` still leaves the earlier spans stored, `run_tool` outside an investigation records nothing, the API returns the trace and `recorded: false` for a case without spans.
- `web/src/__tests__/trace.test.tsx`: collapsed by default; opening shows the totals line and rows in order with the labels above; bar widths are proportional to durations; the failed check says "couldn't run"; no engine ids, tool names or model names in visible text; the unrecorded message. Add the trace to the plain-language test's case render.
